# 04. マイク・スピーカーの準備

声の再現度は **録音の音質で決まります**。マイクの準備を丁寧に行ってください。

## 1. マイク(USB・単一指向性を推奨)

1. USB マイクを Mac に接続します。
2. **口元から 10〜20cm** の位置に、口のほうへ向けて置きます(周囲の騒音を拾いにくくなります)。ポップガードがあるとよいです。
3. 会場の騒音源(スピーカー、通路)にマイクの背面を向けます。

### macOS で入力デバイスを選ぶ

1. 「システム設定」→「サウンド」→「入力」タブ。
2. 使うマイクを選びます。
3. 「入力音量」を調整します。声を出したとき入力レベルの目盛りが **半分〜7割程度** 振れ、端まで振り切らないのが目安です。
4. 細かい確認は「Audio MIDI 設定」(Launchpad で検索)で、マイクが認識されているか、サンプルレートが 44.1kHz または 48kHz かを見ます。

### Chrome で入力を選ぶ

1. Chrome で `chrome://settings/content/microphone` を開きます。
2. 「使用するマイク」で該当 USB マイクを選びます。
3. `http://localhost:8000`(または 127.0.0.1)を **許可** に設定します。ブロックになっていれば「許可」に変更します。

### Windows

「設定」→「システム」→「サウンド」→「入力」でマイクを選び、「デバイスのプロパティ」で音量を調整します。Chrome の選択は上と同じです。

## 2. スピーカーの置き場所と音量(プライバシー R-04)

体験者が話した失敗の内容が、通話音声で周囲に聞こえてしまうことがあります。

- スピーカーは **体験者の近く(耳の高さ、50cm 以内)** に置き、音量を抑える
- ブースをパーティションや布で囲み、外に向けない
- 着信音は目立たせたいが通話は静かにしたい、という調整は次の 2 項目で行う
- 可能ならスピーカーとマイクを離す(通話音がマイクに入るのを避ける)

## 3. 音量の調整

`config.yaml` の `audio` を編集します。

```yaml
audio:
  ringtone_volume: 0.8   # 着信音(0〜1)
  call_volume: 1.0       # 通話音声(0〜1)
  ambient_volume: 0.12   # 環境音(0〜1。下の 4 も参照)
```

- まず Mac 本体のスピーカー音量(または外部スピーカーのつまみ)を「中くらい」に固定し、以降は上記の設定だけで調整します。
- 会場が騒がしい: `ringtone_volume` を上げる。通話が周囲に漏れる: `call_volume` を 0.6〜0.8 に下げる。
- 変更後はサーバーを再起動します。

## 4. 返事の検知と環境音の調整

物語の途中の問いかけ(「覚えてる?」)のあと、アプリはマイクの **音量だけ** を見て、体験者が答えているかを判断します(録音・送信はしません)。また、通話中はカフェのような環境音がかすかに流れます。この 2 つは **スピーカーの音がマイクに入る**(回り込み)と互いに影響します。

```yaml
experience:
  reply_wait:
    speech_threshold: 0.03   # 話していると判定する音量(RMS 0〜1)
    min_pause_sec: 0.6       # 再生停止から判定開始までの秒数
audio:
  ambient_volume: 0.12       # 環境音の音量
```

調整の手順(会場の実際の音量・置き方で):

1. 体験を通し、問いかけの後に **黙っている** テストをします。5 秒ほどで続きが再生されれば正常です。
2. 声を出していないのに待ちが終わらない(最大 15 秒で打ち切られる)場合: 環境音・周囲の騒音・スピーカーの回り込みがしきい値を超えています。`speech_threshold` を上げる(0.03 → 0.05)、`ambient_volume` を下げる(0.12 → 0.06)、`call_volume` を下げる、スピーカーとマイクを離す、のいずれかを行います。
3. 次に、問いかけの後に **普通の声で「うん、覚えてるよ」** と答えます。話し終えて 1 秒あまりで続きが再生されれば正常です。答えているのに反応せず 5 秒で進む場合は `speech_threshold` を下げます(0.03 → 0.02)。
4. 声が小さい人でも反応するよう、必要に応じて macOS の入力音量も見直します。

回り込みを減らすコツ:

- スピーカーをマイクの真後ろではなく **横や後ろ向きに離して** 置く。マイクの背面(感度の低い側)をスピーカーへ向ける。
- スピーカーの音量を抑える。ヘッドホンやイヤホンでの体験も有効(体験者にだけ聞こえるので、プライバシーにもよい)。
- 環境音が邪魔なら `audio.ambient_enabled: false` で切れます。反応が不安定なときは `experience.reply_wait.enabled: false` にすれば待たずに続きが再生されます。

## 5. 会場での事前テスト手順(N-20)

開場前に、**会場の実際の騒音状態で** 次を行います。

1. サーバーを起動し(`scripts/start.command`)、待機画面から体験を最後まで通します。
2. 録音で 30 秒ほど話し、音量メーターが十分振れるか、「声が小さい」警告が出ないかを確認します。
3. 着信音がブース内で聞こえ、ブース外で気にならないかを確認します。
4. 通話音声が体験者に聞き取りやすく、外へ漏れないか、別のスタッフに離れた位置で聞いてもらいます。
5. 認識や声の似方が悪いときは、マイク位置・入力音量を見直します。
6. 問いかけのあとの返事待ちと環境音を確認する(上の 4)。
7. 調整値を `config.yaml` に書き、再起動して再確認します。
8. 練習の録音データは体験終了時に自動で消えます。
